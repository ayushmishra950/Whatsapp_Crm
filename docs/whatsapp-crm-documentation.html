In one sentence: WhatsApp CRM lets you (the platform owner) sell a monthly WhatsApp business tool to many companies. Each company connects its own WhatsApp number, and its team uses it to reply to customers, sort leads, run bulk campaigns and automate replies, with every company's data kept separate.

At a glance

3 login roles

Super Admin (platform owner), Admin (business owner), Agent (business staff). Customers/leads are contacts, not logins.

1 number per business

Each business connects one official WhatsApp number (Meta Cloud API). Unlimited team members can share it, within the plan limit.

Monthly plans

Plans set limits on agents, contacts and messages per month. The Super Admin renews subscriptions and can suspend a business.

1. Product overview

WhatsApp is where Indian customers reply fastest, but most businesses manage it from one phone. Messages get missed, nobody knows which lead is interested, and sending offers to hundreds of people means forwarding one by one or risking a ban with unofficial tools.

WhatsApp CRM turns one official WhatsApp Business number into a shared, organised system for the whole team:

  • Team Inbox: every chat in one screen, on any number of computers at once, with chats auto-assigned to agents.
  • Leads & pipeline: every person who messages becomes a lead with a status (New, Interested, Converted, Not interested…), tags, notes, follow-up reminders and custom details.
  • Bulk campaigns: send approved WhatsApp templates to a list, a status group, a tag or an Excel sheet, now or at a scheduled time, with delivery and read reports.
  • Chatbot: answers common questions 24×7 with a menu, collects lead details, and hands the chat to a person when needed.
  • Facebook / Instagram ads: leads from Click-to-WhatsApp ads are tagged with the ad they came from, so you can see which ad brings leads and conversions.
  • Multi-business SaaS: the platform owner (Super Admin) hosts many businesses, each with its own number, team, data and monthly plan.

4. Roles & permissions

Super Admin

Platform owner

Runs the platform. Creates businesses, plans and subscriptions, suspends/activates businesses, logs in as a business admin for support, sees all audit logs. Does not chat with customers.

Admin

Business owner

Full control of one business: WhatsApp number, team, templates, campaigns, chatbot, settings, all chats and reports.

Agent

Business staff

Handles customer chats: sees chats assigned to them plus unassigned ones, replies, updates leads. Cannot change business settings.

Customers / leads ("User") are not logins. They are contacts stored inside one business. Every business sees only its own contacts, chats and campaigns.

5. Features in detail

5.1 Dashboard

  • Open, pending and unassigned chats; new leads today; total contacts.
  • Messages received and sent in the last 7 days (chart).
  • Lead pipeline with counts per status, linking to the filtered contact list.
  • Follow-ups due today (agents see their own), leads from ads in the last 30 days with conversions.
  • Plan usage this month (messages used / limit) and recent campaigns.
  • Team performance (admin, 7 or 30 days): chats handled, open chats, messages sent, leads converted, median reply time per member, plus chatbot stats.

5.2 Team Inbox

  • Real-time chat list with filters: Open / Pending / Resolved / All, assigned to me, unassigned, bot handling, by agent, by lead status, leads from ads, and search.
  • Send text, images, documents, video, audio and approved templates. The 24-hour window is shown; outside it only templates can be sent (a WhatsApp rule).
  • Quoted replies (both directions), customer reactions, internal notes visible only to the team.
  • Delete own message within 48 hours (removed from the CRM; WhatsApp has no "delete for everyone" in the API), "Send correction" to resend a fixed text, admin can hide any message. All deletes are soft and audited.
  • Header tools: lead status dropdown, assign to agent, resolve/reopen, Details panel.
  • Details panel: name, ad source, lead status, follow-up with note, tags, custom fields, notes, assignment, chat status, chatbot control.
  • "📣 From ad" card on messages that came from a Click-to-WhatsApp ad.
  • Sound + desktop notification for new customer messages (per browser on/off).

5.3 Contacts / Leads

  • Status tabs with counts; filters for search, tag, source (ads), ad, follow-up (due / overdue / upcoming).
  • Inline status change; edit modal with name, phone, email, status, follow-up, tags, notes, custom fields, opt-out.
  • Select rows or "all N matching" → change status, add tags, delete, or send a bulk message to them.
  • Import Excel (.xlsx) or CSV up to 10 MB / 50,000 rows: automatic column matching, preview, country code added (default 91), every import gets a batch tag, and a "Send bulk WhatsApp message" button for that batch.
  • Export to Excel or CSV with the current filters (admin).

5.4 Lead statuses & automation

  • Default statuses: New, Contacted, Interested, Converted, Not interested. The admin can rename, recolour, reorder, add (e.g. "Call back") or remove them (Settings → Lead statuses).
  • Auto lead status: if the customer writes "interested", "haan interested hu", "interest hai" → Interested; "not interested", "interest nahi hai", "no thanks", "nahi chahiye" → Not interested. Questions and long messages are ignored, Converted leads are never changed, and a "🤖 Auto update" note is added in the chat. Can be turned off in Settings.
  • Who changed the status and when is stored; this feeds the team report.

5.5 Bulk campaigns

  • Audience: all contacts, by lead status, by tags, from a specific ad, hand-picked contacts, or the batch from an uploaded sheet. The number of recipients is shown before sending; opted-out contacts are always excluded.
  • Template + variables: each {{1}}, {{2}} is filled from a contact field (name, phone, email or any custom field) or fixed text. Defaults come from the template and can be changed per campaign. A live preview is shown.
  • Send now or schedule for a date/time; save as draft.
  • Edit draft and scheduled campaigns (name, template, audience, variables, time) until 1 minute before start; "Unschedule" turns it back into a draft.
  • Pause, resume and cancel; report per recipient: sent, delivered, read, failed, skipped. The worker sends at a controlled speed, survives restarts, and pauses automatically when the plan's monthly limit or the subscription runs out.

5.6 Templates

  • Create a template (name, category: Marketing / Utility / Authentication, language, header, body, footer) and submit it to Meta. Status updates (pending, approved, rejected with reason) arrive live.
  • Variables section: for each {{n}} choose what fills it and an example for Meta's review. Stored only in the CRM, so it can be changed any time without re-approval.
  • Edit approved templates: header, body and footer only (name, category and language are locked by WhatsApp). The edit goes back to review, with Meta's limits enforced (1 edit per 24 hours, 10 per 30 days); blocked while a running or scheduled campaign uses the template.

5.7 Chatbot (rule-based)

  • Welcome message with a menu: up to 3 options as reply buttons, up to 10 as a list. Customers can tap, type the number, or type part of the option name.
  • Each option can reply with a message, ask lead questions, or hand the chat to the team; options can add a tag.
  • Keyword replies (contains / exact) for free-typed questions like "fees", "address".
  • Lead questions save answers into the contact (name, email or custom fields) and mark the lead.
  • Business hours with an offline message; "Main Menu" button after answers; restart after silence or after a resolved chat; loop protection.
  • The bot stops as soon as a team member replies or takes over. Numbered markers on the settings page match the live WhatsApp-style preview.
  • Super Admin can switch the chatbot module on or off per plan.

5.8 Facebook / Instagram Click-to-WhatsApp ads

  • When a customer starts a chat from an ad, WhatsApp sends the ad details. The contact gets source "ad", the ad headline and ID (first touch) and the tag facebook-ad.
  • Filter leads by ad, send campaigns to leads of one ad, and see leads and conversions per ad on the dashboard.

5.9 Contact fields

  • Settings → Contact fields: the admin adds, renames or deletes custom fields (Course, City, Fees…). Name, phone and email are built in.
  • Fields are used in template variables, campaigns and chatbot questions, and filled on each contact (Contacts → Edit, Inbox → Details).
  • Extra sheet columns and new chatbot fields are added automatically. A field used by a template, an active campaign or the chatbot cannot be deleted (the screen shows where it is used).

5.10 Team & multi-computer use

  • Admin adds agents (within the plan limit), disables them (their chats return to the unassigned queue) and resets passwords.
  • Auto-assignment gives new chats to active agents one by one (round-robin).
  • Everyone can be logged in on many computers at once; all screens update live.

5.11 Settings

  • WhatsApp number: connect Phone number ID, WABA ID and access token (encrypted), test, disconnect. Sandbox mode until connected.
  • Automation & permissions: auto-assign, allow agents to run campaigns, auto lead status, opt-out keywords.
  • Lead statuses, contact fields, plan & usage, change password, sandbox message simulator for testing.

5.12 Super Admin panel

  • Dashboard: total and active businesses, suspended businesses, plans, monthly recurring revenue, usage.
  • Businesses: create (with admin login), edit, suspend/activate, renew subscription (+N months), change plan, login as admin, reset admin password, delete (with name confirmation).
  • Plans: price, limits (agents, contacts, messages per month), features, chatbot module, active/inactive.
  • Audit logs: who did what, in which business, from which IP.

7. Business model & how to earn from it

The product is built as SaaS (software as a service): you host it once and charge each business a monthly subscription. Each business connects its own WhatsApp number and pays Meta directly for its WhatsApp message charges, so your income is mostly profit after hosting costs.

Main running costs

  • Server (VPS / cloud) and a managed MongoDB (e.g. MongoDB Atlas). A small setup can serve dozens of businesses; scale up as usage grows.
  • Domain and SSL, backups, file storage for media.
  • Support time for onboarding and Meta approvals.
  • WhatsApp message charges are billed by Meta to each business's own WhatsApp account, not to you, unless you choose to resell messages.
Tips to protect profit: keep plan limits realistic (message limits protect your server and the client's Meta bill); collect payment before "Renew"; use "Suspend" for non-payment; charge a setup fee because Meta verification takes effort; offer annual plans.

How to sell it: start with one niche (e.g. coaching institutes in your city), demo the chatbot and ad-lead tracking in sandbox mode, sell the outcome ("no missed enquiries, know which ad brings admissions"), and offer a 7–14 day trial with help on the first campaign.

How billing works in the product

  • Each business has a subscription with a status (trial / active / cancelled) and an end date.
  • Super Admin records a payment with Renew (+N months), or changes the plan.
  • When the subscription ends or the business is suspended, sending stops (chats can still be read), and running campaigns pause.
  • Limits are enforced: adding agents or contacts beyond the plan is blocked; outgoing messages are counted each calendar month and campaigns pause at the limit.
  • Online payment collection (Razorpay/Stripe) is on the roadmap; today payments are collected outside the app and recorded by the Super Admin.

11. Architecture

Users' browsers · Super Admin panel · Admin & Agent app (any number of computers)
Next.js frontend
Pages, forms, live inbox. Talks to the API over HTTPS and Socket.IO.
Express API
Auth, roles, business scoping, validation, REST endpoints, Socket.IO rooms.
Campaign worker
Sends queued campaign messages at a safe speed; resumes after restarts.
MongoDB
All data, every record tagged with its business (tenantId).
Webhook processor
Incoming messages, delivery/read status, ad referrals, template approvals → chatbot → auto-assign.
Meta WhatsApp Cloud API
One number per business; sends and receives messages.

Key design points

  • Multi-tenant isolation: every business-scoped record has a tenantId; all business routes pass through a guard that filters by the logged-in user's business.
  • Real-time rooms: admins of a business, each agent and each user have their own Socket.IO room, so agents only receive events for chats they may see.
  • Incoming message flow: Meta webhook → signature check → find business by phone number ID → save contact/message (+ ad details, auto lead status, opt-out) → push to screens → chatbot → round-robin assignment.
  • Campaign flow: audience snapshotted into recipient rows → worker claims each row atomically → sends template → Meta status webhooks update delivered/read counts.
  • Sandbox mode: without Meta credentials the system simulates sending, delivery and read receipts so everything can be tested.
  • Production: one Node process serves both the API (/api) and the built Next.js frontend on the same domain.

13. WhatsApp rules the product follows

  • Official API only: uses Meta's WhatsApp Cloud API, so numbers are not banned for using the software (they can still be restricted for spam or poor quality, so send only to people who expect your messages).
  • 24-hour customer service window: after a customer's last message you can send any message for 24 hours. Outside it, only an approved template can be sent. The inbox shows whether the window is open.
  • Templates: the first message to a new customer and all bulk messages must use Meta-approved templates. Categories: Marketing, Utility, Authentication. Variables like {{1}} are filled per customer.
  • Template edits: an approved template can be edited up to once per 24 hours and 10 times in 30 days; name, language and category cannot change. Edited templates go back to review.
  • Charges: Meta charges the business for template messages according to its current rate card (it varies by category and country). Replies within the 24-hour window are generally free. Check Meta's pricing page for current rates.
  • Messaging limits: new numbers can message a limited number of unique customers per day; the limit rises as quality stays high and volume grows.
  • Opt-out: customers who reply STOP are excluded from campaigns.

Connecting a real WhatsApp number

  1. Meta Business account + Meta developer app with the WhatsApp product; add and verify the business phone number (not active on the WhatsApp app); add a payment method in WhatsApp Manager.
  2. Meta app → WhatsApp → Configuration → Webhook: Callback URL https://<your-domain>/api/webhook/whatsapp, Verify token = WA_WEBHOOK_VERIFY_TOKEN; subscribe to messages and message_template_status_update.
  3. Put the Meta App Secret in WA_APP_SECRET.
  4. Create a System User with a permanent token (whatsapp_business_messaging, whatsapp_business_management).
  5. In the CRM, Admin → Settings → WhatsApp number: enter Phone number ID, WABA ID and the token → the business switches to live mode.

Production checklist

  • A server (VPS or cloud) with Node.js 20+, a domain and HTTPS (needed by Meta's webhook).
  • Managed MongoDB (e.g. Atlas) with backups; set MONGO_URI.
  • Strong unique JWT_SECRET and ENCRYPTION_KEY; keep .env secret.
  • Build the frontend, then start the backend in production mode (it serves both):
cd web && npm install && NEXT_PUBLIC_API_URL= npm run build
cd ../server && npm install && NODE_ENV=production npm start
  • Run with a process manager (e.g. PM2 or systemd) so it restarts automatically; point the Meta webhook to the domain (a permanent URL, unlike a temporary tunnel).
  • Change the seed passwords after the first login.
